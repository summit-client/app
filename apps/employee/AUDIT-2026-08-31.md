### The two tables with row security on and no policies

`platform_operators` and `hub_certificate_registry`. Row security on with zero
policies denies every API role, which is the intent in both cases:
`platform_operators` is documented in `0017` as service-role-only ("no UI
manages this table in v1"), and the certificate registry is reached only
through security-definer functions. Neither is read by any application. **Not a
finding.**

### Fixed in this branch

1. **Thirty-nine inert policies.** `0013` wrote every policy for the eight
   scheduler tables and never enabled row security on any of them. A policy on
   a table without row security is not consulted. Fixed by `0032`, which also
   refuses to enable row security on a table with no policies rather than
   locking everyone out.
2. **`profiles` had no policies and no row security.** It holds `role` and
   `clinic_id`, so `update profiles set role='admin' where id=auth.uid()` was a
   straight privilege escalation. Fixed by `0032`, with a trigger for the part
   RLS cannot express — self-update must exist so a person can change their own
   name, and without the guard that includes their own role.
3. **Prototype-chain leak on a URL parameter.** `resolveCourseLink` did
   `COURSE_LINKS[key] ?? null` on a key taken straight off the route.
   `"toString"`, `"constructor"` and `"valueOf"` return a function from
   `Object.prototype`, which `?? null` does not catch, and that function reached
   `NextResponse.redirect()`. `/api/course-link/toString` answered 500 where it
   meant 404. `Object.hasOwn` plus a `typeof` check now.
4. **Nineteen reads rendered failure as emptiness.** Every read in the two
   employee-portal stores used `result.data ?? []` and ignored `result.error`.
   A failed query became an empty array indistinguishable from "you have none
   of these" — the trap CLAUDE.md names.

### Open, not fixed here

- **`apps/scheduler/lib/useUser.ts:114` calls `auth.getSession()`** to establish
  client-side identity. Not a hole: `proxy.ts` has already gated the request
  server-side and RLS is the real boundary. It is the cross-portal refresh-token
  race CLAUDE.md documents, though — a `getSession()` on a possibly-stale
  session can redeem the refresh token and invalidate another portal's. Owned by
  another app; logged rather than edited.
- **`apps/scheduler/dump.txt` and `index_dump.txt` are committed.** No secrets in
  either, but they are scratch artifacts carrying stale copies of auth code,
  which is how a reviewer ends up auditing a file nobody ships.
- **`0000` is unverified against production.** It reconstructs eight tables from
  application code. Two errors in it were caught by running the history; a third
  would only be caught by `pg_dump`. See `docs/DEPLOY.md` step 1.

## UI

### Fixed

1. **The comparison table clipped its own answer column on mobile.**
   `.compare-wrap` had `overflow-x: auto` but nothing pinning its width, so the
   table's `min-width: 560px` stretched the wrapper instead of scrolling inside
   it. The page did not scroll sideways — `body` has `overflow-x: hidden` — which
   is worse than it sounds: the Summit column was simply cut off and
   unreachable. `max-width: 100%` makes it scroll in its own box.
2. **Hero stats wrapped 2-then-1** below about 430px, stranding the third
   figure under a gap wide enough to read as a mistake.
3. **The brand mark rendered 32×28.** `.brand-mark` in `@summit/design` is sized
   for the old placeholder SVG's viewBox; the real mark is square, so the shared
   rule stretched it. Only visible by measuring the computed box.

### Checked

- No horizontal page scroll at 320, 375, 390, 430, 768, 1024 or 1440.
- The comparison is a real `<table>`: caption, row and column headers, `tfoot`,
  and text behind each tick so a screen reader hears "Included in Summit".
- Zero gradients in `apps/web`, including the blurred radial blob and the black
  scrim that existed only to rescue contrast over one.
- No fabricated social proof: the invented "trusted by" clinic marquee and the
  invented testimonial are gone, replaced by nothing and by a claims-checkable
  trust section respectively.
- No compliance badge anywhere. PHIPA, PIPEDA and HIPAA are all absent as
  claims; the trust section describes architecture instead, which holds in any
  jurisdiction.

### Open

- The feature list and the comparison table both sit in the same section rhythm
  as everything else on the page. The brief asks for visual variety between
  sections and that has not been done.
- The hero is still a pinned scrollytelling scene. It does demonstrate the
  product rather than decorate, which is the test, but it is the heaviest thing
  on the page and worth a second opinion.
- `apps/web/public/summit-logo.jpg` is 551 KB and unreferenced.
